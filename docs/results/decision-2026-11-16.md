# Bounded follow-up decision: cost, damage, and owner dependence

The one-cycle direct-query candidate does **not establish superiority** over unprotected faulty TAGE in the frozen eight-owner qsort evaluation. Mean paired benefit is **-1.2654%**, with an exploratory 95% owner-bootstrap interval **[-2.8035%, +0.9211%]**. Two owners improve and six lose. The interval crossing zero does not establish equivalence. No additional owners or latency reductions are admitted after inspecting this result.

All 16 evaluation executions and all four E5 controls passed expected output, architectural retirement identity, instruction count and actual event-count checks. There were no timeout, simulator failure, or excluded timing pairs. All 20 share identical System/CPU/cache/memory/BTB/RAS/indirect parameters after removing only the conditional predictor and per-run stdout/stderr paths.

The population is eight new independent forced single-raw-bit event owners on the **same current qsort binary/input**. Raw age is uniform 0..129; integer event ticks are uniform between 10% and 80% of the already measured U0 exit tick. Owner seed 2026111607 and fixed sample size eight were frozen before execution. Both UF and MF use producer `eb80698`; MF has one additional conditional-query cycle and one pending request. There is no calibrated physical event rate, WHOLE coverage, independent-input evidence, lifetime sweep, or tail claim.

## Damage persistence is not sufficient for a speedup

The earlier [native screen](native-screen-2026-11-16.md) found six raw faults whose consumed rolling-fold invariant did not recover before exit, although raw-origin labels disappeared from active and observed restorable histories. Actual runtime penalties ranged from zero to 15.72%. The [causal replay](causal-pilot-2026-11-16.md) also showed residual learning effects and harmful/helpful cancellation after fold-only restoration. Replay remains functional evidence, not CPU timing.

The [direct development comparison](direct-development-2026-11-16.md) has +11.1377% benefit at R0 and -2.7603% at R64, with +2.9199% clean M0/U0 cost. These development owners motivated the frozen evaluation; they are not pooled with it. The evaluation retains a winning case (+5.5840%) and losing cases rather than selecting the damaged subset.

Conditional MPKI uses the committed BPU DirectCond+IndirectCond misprediction counters, not TAGE query disagreements or a fixed miss penalty. Committed conditional density is 6,842,112 / 25,377,774 = 26.9610% in each cell. Redirect and fetch-stall counters are retained in `RESULTS_FINAL.csv`; their raw definitions are not silently equated with final conditional mispredictions.

BASE_FORCED changes only the returned direction while retaining ordinary TAGE internal computation and learning. BASE_MIN instantiates only 8192 prediction bits and 2048 shared hysteresis bits plus branch training ownership, with no history/fold/tagged/chooser state. It trains every committed conditional branch; its stream need not equal the base table trained under TAGE selection. Both retain common BTB/RAS/indirect settings.

BASE_MIN clean is approximately 27.76% slower than U0, so prediction quality remains valuable on this input even after removing history state. The common base-counter fault pair is a separate environment from the raw-only evaluation: one prediction bit chosen from the first clean conditional PC at/after the fixed quarter tick, with the same site/tick in both methods. It caused no final runtime change here; BASE_MIN remains slower. This single zero-damage counter case does not establish global counter/control resilience. Removed raw/fold sites are N/A, not zero-loss WHOLE evidence.

## Necessary-cost and evidence boundary

| Method | Measured/model cost included | Unmeasured terms |
|---|---|---|
| U_NATIVE | Ordinary TAGE query/train/speculation, no added helper/checker | Physical source, table, checkpoint, control timing/energy/area |
| D_QUERY | Own current raw/path hashes; additional 1-cycle conditional-query admission; one pending request with cancellation; ordinary raw updates/train/speculation | 1-cycle physical feasibility, raw fanout/read ports, controller protection, layout and energy |
| BASE_FORCED | Full ordinary TAGE work with base-only returned direction | Physical cost retained; not a minimal architecture |
| BASE_MIN | 10,240 logical base bits, ordinary base read/train and branch marker; shared BPU controls | Physical read/update/control timing, faults outside exposed base bits, area/energy |

Dead rolling-fold fields in the direct simulator are software bookkeeping, not consumed direct hardware state; stored-fold injection is N/A for that candidate. Finite B4 common checker/vector costs are not required native/direct costs and are not used to claim this comparison. Prior small 28 nm blocks and installed GPDK45 do not establish matched full-source/checkpoint/controller PPA; those quantities remain UNKNOWN. No RTL/Cadence/PDK execution occurred.

## Decision and stopping boundary

Keep unprotected TAGE as the runtime reference. Direct folding removes a persistent error mechanism and helps some sufficiently damaged owners, but this one-cycle implementation does not show an average advantage in the frozen owner population. The minimal-base control loses substantial clean prediction quality. These results support studying protection only where damage is sufficiently costly to repay normal overhead; they do not justify a broad method/rate/lifetime campaign or an uncharged repair oracle.

The bounded development/evaluation batch is complete and stops at its declared count. E6 used one direct-query candidate; no new adaptive/short-history/repair design is inferred from a favorable case. E7/E9 environmental rate/lifetime and independent-workload expansion remain deferred. Full CPU learning/RNG-state recovery, final BPU per-query direction/target recovery, and physical PPA are not observed in this batch. The timing and conditional-performance conclusions above do not substitute estimates for those missing quantities. Historical completed evidence is accepted as reported; no extra historical hash/authenticity reproduction batch was run after the user priority amendment.
